% ---------- ABSTRACT ----------
\begin{abstract}
Customer churn is a major business challenge in subscription-based telecom services. This project builds a churn prediction pipeline using the Telco Customer Churn dataset, focusing on data cleaning, categorical encoding, model training, evaluation, and deployment through a Streamlit interface. We compare Logistic Regression and Random Forest classifiers on the cleaned dataset, report classification metrics, and provide reproducible artefacts including trained models, encoders, and feature importance outputs. The final outcome is an end-to-end system where users can upload a CSV file and obtain churn predictions along with basic analytics and downloadable results.
\end{abstract}

\begin{IEEEkeywords}
customer churn, classification, logistic regression, random forest, preprocessing, streamlit deployment
\end{IEEEkeywords}

% ---------- INTRODUCTION ----------
\section{Introduction}
Telecom operators face recurring revenue loss when customers discontinue their subscriptions. Predicting churn in advance enables targeted retention actions such as plan optimisation, personalised offers, and service interventions. The goal of this project is to design an end-to-end churn prediction system: (i) clean and encode the Telco dataset into a machine-readable format, (ii) train and evaluate baseline and ensemble machine learning models, and (iii) deploy a simple web interface for users to generate predictions from uploaded customer records.

\section{Problem Statement}
Given customer-level demographic and service usage information, predict whether a customer will churn (binary classification). The outcome supports early identification of high-risk customers.

\section{Methodology}

\subsection{Dataset Description}
We use the Telco Customer Churn dataset (Kaggle), which contains customer demographics (e.g., gender, senior citizen), subscription services (e.g., internet service, streaming), billing details (e.g., monthly charges, total charges), and a churn label. The label indicates whether a customer left the service.

\subsection{Preprocessing}
Preprocessing aims to produce a consistent numeric feature matrix suitable for machine learning.
Key steps include:
\begin{itemize}
    \item \textbf{Missing value handling:} blank \texttt{TotalCharges} values are coerced to numeric and missing entries are filled with 0.
    \item \textbf{Column removal:} non-informative identifiers such as \texttt{customerID} are removed.
    \item \textbf{Categorical encoding:} categorical values are converted to numeric using saved label encoders (\texttt{label\_encoders.pkl}).
    \item \textbf{Feature alignment:} the UI aligns incoming CSV columns to the expected feature list stored in \texttt{feature\_names.json}.
\end{itemize}

\subsection{Models Used}
We trained and compared two models:
\begin{itemize}
    \item \textbf{Logistic Regression (LR):} a linear baseline model for binary classification.
    \item \textbf{Random Forest (RF):} an ensemble of decision trees to capture non-linear feature interactions.
\end{itemize}

% ---------- DISCUSSION ----------
\section{Discussion}
Random Forest typically performs better on this dataset due to non-linear interactions between service subscriptions, tenure, and billing attributes. Logistic Regression offers interpretability and can serve as a strong baseline. Limitations include sensitivity to how categorical variables are encoded and potential dataset imbalance, which can inflate accuracy while underperforming on minority churn cases. Future work could include calibration, threshold tuning, and more robust encodings (e.g., one-hot encoding) depending on deployment requirements.
